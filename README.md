# Canopy

Canopy is a versioned tree editor with an infinite-pan history graph, nested treemap views, branch comparison, subtree editing, cycle-safe drag operations, and shared-session presence.

The retractable sidebar contains workspace status, editing actions, comparison, graph navigation, and shared-session controls. In a shared room, the collaborator list shows each user's color, animal name, and active version; click a collaborator to focus their version without changing your own active version. The **Interaction Log** keeps the ten most recent shared actions, with navigable references to existing entries, versions, and ping locations. Each version has an independent, scrollbar-free treemap canvas. Nested entries use a balanced two-dimensional layout; top-level treemaps avoid overlap, preserve their positions where possible, and zoom out when a layout expands. The mouse wheel zooms the full version graph, including when the pointer is over a version canvas. Use Shift + the mouse wheel to zoom only that version canvas and Shift + left-drag to pan it. Click an entry to select it; Shift-click adds or removes entries in a multi-selection. Right-click entries and versions for contextual actions; right-click empty canvas space for current-canvas actions. Entry deletion can keep children attached to their former parent, delete the whole subtree (with confirmation), or detach children as free entries. Entry editors focus the value field automatically. Descriptions appear after hovering over an entry for two seconds. Within each version, entries with exactly matching values are connected by non-interactive lines, with one connection per relationship and no arrowheads. Dragging starts after a small pointer movement, selects the entry, keeps a dashed outline at its original position, and previews the unchanged-size subtree above other entries without reflowing its former parent. Hover, selection, and drop-target states change the entry's own stroke; it transitions from 3px when zoomed in to 10px when zoomed out. Drag over a valid entry to preview attachment; moving a nested entry outside its parent previews a detach. Child layout remains automatic rather than being manually reordered by dragging. Invalid and outside drops are canceled, and any zoom-out needed to show a preview is retained. Click the active-version card in the sidebar or press **F** to focus it. Use **Alt + click** or the **Ping** control to mark a position for collaborators, and toggle dark mode in the sidebar.

The entry editor supports adding multiple entries in one version. Select multiple entries to delete them together while choosing whether to keep, remove, or detach their children. Use **Merge entries** to combine a selection into one entry while preserving its descendants, or **Split entry** to replace one entry with multiple entries and assign each direct child to a result. Version cards resize with the browser viewport while preserving their contents and hierarchy.

Focusing a version and fitting the graph are animated. Copying an entry creates a dashed connector directly between the source and copied entries; click it once to activate and focus the version at the opposite end. The connector follows both entries through layout and viewport changes, and disappears when either linked version or entry is removed. When adding an entry to an empty branch, the new version automatically centers all elements. At low graph zoom, versions switch to a read-only summary showing the action and entry/treemap counts.

Open a version's **three-dots** menu to focus the version, center and fit all of its treemaps, or pack them into a compact, overlap-free layout that accounts for both canvas dimensions. **Compare** opens a linked side-by-side view that distinguishes additions, removals, edits, and hierarchy or position changes. Press **M** or choose **Merge** to open a separate, vertically aligned merge view: choose source and target entries, omit entries, adjust their result parent, and preview the merged hierarchy before confirming. The Merge View is modal while comparing two versions and scrolls independently of the graph. With no choices, versions are combined by entry identity; new merge versions are compacted automatically. Merges preserve both histories, add normal midpoint-routed connectors from both source versions to the result, and place the result one step after the later source. Merging from a non-latest target starts a dedicated lane between the source and target branches.

Use **F** to focus the active version, and the **arrow keys** to move to the previous or next version on the current history path, or to the closest version on the branch above or below. **Ping** (or **P**) toggles Ping Mode; click the canvas to place a ping, and press **P** or **Esc** to exit. Canvas drags continue to pan without placing a ping.

## Rooms and shared sessions

At startup, Canopy opens the last locally saved room, or creates one if needed, and automatically hosts or joins it. **Change Room** lets you switch between saved rooms, create an empty room, or delete an inactive room after confirmation. **Copy Invite** copies a link that opens the same room for collaborators. Each room keeps its own versions, entries, interaction log, collaboration metadata, and copied-entry clipboard in browser storage. The current user appears in the Collaborators list and local actions are recorded in the Interaction Log even when no other users are connected.

All connected peers can edit and create branches, including from the root version. WebRTC carries shared edits and temporary user presence between peers; PeerJS's public signaling service is used to establish connections. Each participant has an independent active version and selection, highlighted using a stable user color. The host browser must remain open and connected for the room to remain available. Concurrent changes to different versions merge; simultaneous changes to the same version use deterministic last-writer-wins conflict resolution.

## Run locally

```sh
npm install
npm run dev
```

The Vite UI runs at `http://127.0.0.1:5173`. Room state is persisted in browser storage in both development and deployed builds; the local workspace API is not used for room data.

For a production build, run `npm run build` followed by `npm start`. The production server serves the built UI and the same workspace API on port `4173`.

## GitHub Pages

The workflow in `.github/workflows/deploy.yml` builds and deploys the static site to GitHub Pages on pushes to `main` and on manual runs. The build automatically uses the repository subpath (or the domain root for a `*.github.io` repository). Enable **GitHub Actions** as the Pages deployment source in the repository settings.
