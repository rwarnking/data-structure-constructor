# HIVERSE

HIVERSE is a versioned tree editor with an infinite-pan history graph, nested treemap views, branch comparison, subtree editing, cycle-safe drag operations, and shared-session presence.

The left sidebar contains workspace status and shared-session controls. A collapsible right sidebar groups actions and shortcuts by scope. In a shared room, the collaborator list shows each user's color, animal name, and active version; click a collaborator to focus their version without changing your own active version. The **Interaction Log** keeps the ten most recent shared actions, with navigable references to existing entries, versions, and ping locations. Each version has an independent, scrollbar-free treemap canvas. Nested entries use a squarified layout; top-level treemaps can overlap when moved manually. The mouse wheel zooms the full version graph. Shift + the mouse wheel zooms a version canvas; Shift + left-drag pans it. Directional indicators show where entries are fully outside the version viewport, combining entries in the same direction. Dragging empty space in a focused version pans the graph without Shift. Click an entry to select it; Shift-click adds or removes entries in a multi-selection. Right-click entries and versions for contextual actions; right-click empty canvas space for current-canvas actions. Entry deletion can keep children attached to their former parent, delete the whole subtree (with confirmation), or detach children as free entries. Entry editors focus the value field automatically. The full entry name and description appear after hovering briefly. Leaf labels wrap at word or hyphen boundaries; parent labels stay on one line. Both truncate when space is insufficient. Within each version, entries with exactly matching values are connected by non-interactive lines, with one connection per relationship and no arrowheads. Dragging starts after a small pointer movement, selects the entry, keeps a dashed outline at its original position, and previews the unchanged-size subtree above other entries without reflowing its former parent. Treemaps overlapping another treemap underneath have a dotted black outline; the most recently dragged treemap is brought to the front, and the valid drop target is highlighted. Entries have white outlines; a colored outline marks entries added, modified, or changed in hierarchy or order relative to the version's parent, including merge and split results. Treemap positioning alone does not mark entries as changed. Dropping on a valid entry attaches to the topmost entry under the pointer. If the attachment expands its treemap into others, conflicting treemaps move together in the direction of expansion, including cascading conflicts; each treemap moves at most once, so overlaps may remain in complex cases. Unrelated manual overlaps are preserved. Dropping on the dragged entry, one of its descendants, or empty space moves it; a nested entry becomes a free treemap. After a move, the treemap view zooms in to fit the layout where possible without clipping content; the version window stays the same size. Child layout remains automatic rather than being manually reordered by dragging. Outside drops are canceled; other entries and the map view stay fixed until a move is committed. Double-click a version header, click the active-version card in the sidebar, or press **1** to focus it. Use **Alt + click** or the **Ping** control to mark a position for collaborators, and toggle dark mode in the sidebar settings.

The entry editor uses a scrollable, one-line-per-entry table for adding multiple entries in one operation; all rows are validated before one new version is created. Select multiple entries to delete them together while choosing whether to keep, remove, or detach their children. Use **Merge entries** to combine a selection into one entry while preserving its descendants, or **Split entry** to replace one entry with multiple entries and assign each direct child to a result. Version cards resize with the browser viewport while preserving their contents and hierarchy.

Single-click a version to activate it without moving the graph; double-click its header, overview, or empty canvas to activate and focus it at any zoom level. Double-clicking an entry still opens its editor. Compare and merge start with the active version selected first. Deselect it in the selection panel to choose another; single-click a version to pick it for the operation.

Focusing a version and fitting the graph are animated. New cards animate into place before their terminal arrows appear. Curved branch and merge connectors appear above straight connectors. Action symbols are shown in destination version headers, not on connectors. Copying an entry creates a dashed connector directly between the source and copied entries; click it once to activate and focus the version at the opposite end. The connector follows both entries through layout and viewport changes, and disappears when either linked version or entry is removed. When adding an entry to an empty branch, the new version automatically centers all elements. At low graph zoom, versions switch to a read-only summary showing the action, tag, and entry/treemap counts. The empty root is labeled “Root: Empty” and uses this summary at all zoom levels.

Hover a low-zoom summary to preview its treemap, or hover its tag for the title and description. In a manually positioned graph, resizing preserves the active card's position where possible. Bulk add and delete titles show the number of entries rather than listing their names.

Open a version's **three-dots** menu to focus the version, center and fit all of its treemaps, or pack them into a compact, overlap-free layout that accounts for both canvas dimensions. **Compare** opens a viewport-sized, linked side-by-side view that distinguishes additions, removals, edits, and hierarchy or position changes. Press **Shift+M** or choose **Merge** to open a viewport-sized merge view with an interactive result treemap, a depth-first entry list, and a source-change summary. Pick or omit entries, adjust result parents, or reorganize the preview; these controls stay synchronized, and **Reset** restores the initial preview without changing either source version. With no choices, versions are combined by entry identity; new merge versions are compacted automatically. For unequal steps, the higher-step version is merged into the lower-step version regardless of selection order. Equal-step merges retain selection order. Merges preserve both histories, add normal midpoint-routed connectors from both source versions to the result, and place the result one step after the later source. An unequal-step merge continues the target's lane if it is a branch tip and otherwise starts a new lane. For equal steps, it continues the target's lane if possible, otherwise the source's lane, and starts a new lane if neither is a tip.

Older merges that unnecessarily used a separate lane are reflowed where safe; their existing version numbers remain unchanged.

Use **1**, **2**, **3**, and **4** for focus, neighborhood, fit height, and fit all. The focused card shows how many later versions exist. Neighborhood focus frames the predecessor, current version, and successor when present, while keeping other visible versions on screen; fit height centers the complete branch height and the active version horizontally. Graph zoom cannot exceed the focused-version zoom. Presets adjust to the available canvas. Arrow keys navigate adjacent versions or timelines; **Page Up/Down** select the first or last timeline, and **Home/End** select the first or last version in the active timeline. **Alt+click** sends a ping; the Ping control can also toggle Ping Mode, which **Esc** exits.

Use **+** and **-** to step between the same zoom presets. The action sidebar provides preset zoom and search buttons in both expanded and collapsed states. In compare and merge treemaps, **Shift+wheel** zooms, **Shift+drag** pans, and **Shift+A** resets the view.

The collapsed left sidebar retains Change Room, collaborator navigation, and a compact clickable interaction log. Settings provide a local sound volume and mute control, plus a room-wide branching toggle. Sound starts muted in every new room session; volume remains saved. When branching is disabled, creating versions from non-tip versions is blocked; merges require both selected versions to be tips. Concurrent edits made before peers receive each other's changes can still produce branches.

Press **Ctrl/⌘+F** outside a text field to search across version identifiers, tags, actions, and entry names or descriptions. Use **All** to search every type, or combine individual fields to narrow the results. Select a result to activate and focus its version. The three most recent queries and selected results are stored locally and are not shared; selecting a recent result reopens it in the same room, or restores its query in another room. Press **Esc** to close search.

Press **Ctrl/⌘+Z** to remove the most recently created version and return to its parent, and **Ctrl/⌘+Y** to restore it. Only one undo/redo step is available; creating another version, switching rooms, or reloading clears redo. Undo and redo synchronize with collaborators, and a version referenced by another version cannot be undone. The expanded action sidebar also provides undo, redo, and search controls.

Use **Ctrl/⌘+drag** from empty space in an editable version to box-select intersecting entries; add Shift to extend the current selection. Drag a selected entry to move the selected subtrees together. A context menu's **Add parent** action wraps the selection in one new entry, attached to the first selected entry's former parent.

**Add child** creates an independent child with the entered value under each selected entry in one version. A version's menu can add, edit, or remove its tag; hover its indicator for the title and description. Tags belong to individual versions, remain on those versions when branching, and synchronize with the room. Open **Show tagged versions** in settings to navigate the room's tagged versions.

The circled exclamation button opens an interactive tutorial; it can be skipped or restarted. Its steps are defined in `src/content/tutorial.json`, including optional lists, images, UI highlights, click completion conditions, and demonstration actions. Keyboard mappings and action icons are centralized in `src/config/hotkeys.ts` and `src/config/icons.ts`. Core light and dark theme colors are configured in `src/config/theme.css`.

Lane-edge arrows pan to the first or last non-root version in that lane without changing the active version. Their color matches the destination version; the active version's lane buttons are 1.5 times wider. Their height follows the visible portion of the lane.

Use **Ctrl/⌘+A** to select all entries in the active version, **Ctrl/⌘+C** to copy selected subtrees, and **Ctrl/⌘+V** to paste them. **Ctrl/⌘+X** prepares selected subtrees for cutting: paste into a different version to create a copy there and a separate deletion version from the original source. Selected descendants of another selected entry are included once. Text fields retain their normal shortcuts. **Ctrl/⌘+O** also focuses the active version, and **Ctrl/⌘+N** opens the new-entry editor.

Version numbers normally have the form `step.branch.subbranch`. Each original branch starts at subbranch `001`; only a new fork increases it. If numbers collide, for example after simultaneous edits or reuse of a deleted version's step, a fourth part counts from `1` to distinguish them. Independently created versions can temporarily have the same number, and displayed suffixes may change as peers synchronize. Numbers deleted after this update remain reserved. Numbers are independent of visual lanes, and existing rooms are migrated when loaded.

## Rooms and shared sessions

At startup, HIVERSE opens the last locally saved room, or creates one if needed, and automatically hosts or joins it. **Change Room** lets you switch between saved rooms, create an empty room, join by room name or invite URL, or delete an inactive room after confirmation. **Copy Invite** copies a link that opens the same room for collaborators. Each room keeps its own versions, entries, collaboration metadata, copied-entry clipboard, and ten recent sidebar interactions in browser storage. The root must be empty; imports and saved rooms with root entries are rejected without changing their data. The current user appears in the Collaborators list and local actions are recorded in the Interaction Log even when no other users are connected.

The sidebar settings menu contains the theme toggle and data import/export. Exports are self-contained JSON objects with `format: "canopy-dataset"`, `version: 1`, the room name, its graph `state`, and recent `interactions`. Imports validate the file and create a separate local-only room; name collisions receive `_1`, `_2`, and so on. Large locally stored room snapshots are compressed to reduce browser storage usage. Imported rooms do not connect to a shared room or provide an invite, including after reload.

Settings also offers **Export Interaction Log** and **Replay Interaction Log**. The exported JSON includes the current room's initial state, recorded inputs and committed changes, and collaborator identities. If replay validation fails, export downloads the unvalidated recording with a `-raw` suffix and displays an error; this file may not be replayable without repair. Replay uses a local-only room named `Interaction Log Replay`, replacing its previous contents even if it is active; other rooms are preserved. Playback follows the recorded timing, including idle gaps; **Skip to next step** or the arrow keys step through events. The toolbar remains fixed to the current window while the recorded view scales. New recordings include browser size and sidebar layout changes so replay can scale the recorded view to the current window, and record shared changes as each participant saw them. Older recordings lack these dimensions; enter the participant's original browser viewport width and height and sidebar layout in the replay toolbar if known. Entry creation, editing, splitting, merging and deletion dialogs, branch merge choices, and tag drafts are shown during replay; older logs reconstruct them where their recorded inputs allow. Cursor movement between recorded positions is interpolated during playback, not captured continuously; stepping shows the last recorded position. The initial room state appears when playback starts because its earlier creation interactions may not be recorded. The complete recording is held in page memory and is lost on reload or closing the page unless exported; the separate sidebar history retains only the ten most recent meaningful actions in local storage. Exports can contain entered text and cursor positions, so share them carefully.

The analysis view includes a user-by-action matrix, per-user action flow, graph viewport heatmap, and version activity map. Select a visualized count or area to inspect its recorded events. **Abstract interactions** groups related recorded actions for analysis without changing the exported log or replay; selecting a grouped action shows its underlying records. Raw counts represent log records, not necessarily distinct operations. Activity intervals begin with the first recorded change, while input timestamps remain available for latency analysis. The heatmap estimates time between a user's events at their last recorded graph viewport origin; it can include idle time and excludes version-canvas viewports and unrecorded periods.

All connected peers can edit and create branches, including from the root version. WebRTC carries shared edits and temporary user presence between peers; PeerJS's public signaling service is used to establish connections. The host assigns distinct animal names and palette colors within the room, reusing colors or numbering names only when the available choices are exhausted. Each participant has an independent active version and selection. When a peer creates a version, participants viewing its parent follow the new version; participants viewing other versions stay where they are. When a viewed branch is deleted, participants move to its nearest surviving ancestor. A departing host hands the room to a connected peer; after an unexpected loss, multiple surviving peers can elect a replacement. A disconnected peer retries the existing room and is warned if it cannot reconnect. A lone peer cannot distinguish an unexpected host loss from a closed room, so it is warned instead of automatically creating a room. Concurrent changes to different versions merge; simultaneous changes to the same version use deterministic last-writer-wins conflict resolution.

## Run locally

```sh
npm install
npm run dev
```

The application entry point is `src/App.vue`, with workspace composition in
`src/views/` and UI in `src/components/`. The `src/composables/` directory
contains the workspace's history, hierarchy editing, graph, comparison, and
collaboration controllers. Room persistence is in `src/services/`, shared types
are in `src/types/`, and tree, layout, and validation helpers are in `src/utils/`.
Peer connectivity is implemented in `src/collaboration.ts`.

Treemap cards render only tiles near their visible canvas; layout, selection, dragging,
and duplicate and copy connectors still use the complete version data.

The Vite UI runs at `http://127.0.0.1:5173`. Room state is persisted in browser storage in both development and deployed builds; the local workspace API is not used for room data.

For a production build, run `npm run build` followed by `npm start`. The production server serves the built UI and the same workspace API on port `4173`.

## Tests

Install the browser once with `npx playwright install chromium`, then run
`npm test` for both unit and browser integration tests. Run `npm run test:unit`
or `npm run test:ui` separately, and `npm run typecheck` for a non-incremental
type-check. The browser suite starts its own Vite and PeerJS signaling servers
on ports 19100 and 19101; it uses real local WebRTC connections without relying
on the public signaling service. Each test uses isolated browser storage.

## GitHub Pages

The workflow in `.github/workflows/deploy.yml` builds and deploys the static site to GitHub Pages on pushes to `main` and on manual runs. The build automatically uses the repository subpath (or the domain root for a `*.github.io` repository). Enable **GitHub Actions** as the Pages deployment source in the repository settings.
